## 比較設定與證據

- 快照：`gpt-4.1-mini-2025-04-14`；temperature 0；每次最多 500 output tokens。
- 原始碼版本：`f3353aa`。兩者共用模型設定、工具目錄、政策、輸入 schema 與業務服務。
- 固定流程預先讀取 context，再用一次模型解析；Agent 自行選擇工具，每輪最多六步。
- 相同案例各跑一次，使用不同 SQLite 檔案，交替策略先後順序。沒有失敗後換提示再挑結果。
- 預算授權：USD 1、最多 144 次請求；實際為 USD 0.0100752、33 次。
- 價格：每百萬 noncached input / cached input / output tokens 分別為 USD 0.40 / 0.10 / 1.60，執行前已核對。[官方模型與價格](https://developers.openai.com/api/docs/models/gpt-4.1-mini)

原始 [摘要](summary.json)、[逐案結果與提議](cases.json)、[用量帳本](usage-ledger.jsonl)、
[版本與檔案雜湊](manifest.json) 已保存。Manifest 在執行期間記錄；執行後再次確認六個原始碼檔案雜湊均未改變。
用量帳本保存 usage 與 response ID，但沒有逐請求保存 provider 回傳的 model 名稱；模型設定的依據為原始碼與 manifest。
完整 SQLite 證據留在本機 `artifacts/paid-pilot-01/`，不提交資料庫。

## 稽核與限制

獨立唯讀稽核重新檢查了 24 個資料庫、四筆受保護的他人預約、操作版本、提交數與費用公式，沒有發現數字不一致。
另外檢查反悔／過期確認的四個後續回覆，模型均使用 `finish`，沒有新提議；原操作取消且無預約。
這項 [執行後 DB 稽核](post-run-reversal-audit.json) 為補充證據，沒有改動原始分數。

- 12 情境只有六種不同初始提示；多個案例是相同預約提示加不同系統故障。反悔與過期確認在本輪走相同測試路徑，不能視為兩項獨立能力證據。
- 重試、查證、恢復、確認事件主要由確定性的測試使用者與後端執行。結果證明模型能接入此系統，不代表模型能自主恢復任意外部交易。
- DB 分數逐欄比對，不使用 LLM judge。查詢只檢查指定預約 ID，拒絕使用固定詞彙，不能完整評估語意品質。
- 原評分不檢查反悔的第二輪回覆，因此另外做了 DB 稽核；本輪未觀察到誤判，不表示評分器對所有輸出都完備。
- 每策略僅 12 樣本，nearest-rank p95 等於最大值。延遲包含模型及本機業務處理、排除資料初始化；不是一般服務的尾延遲證據。
- 尚未做未見題組、多次重複實驗或更廣泛的注入攻擊測試。

目前網頁仍預設免費 mock。真實模型只用於本次明確授權的比較，不會因 `.env` 存在就讓互動介面持續產生費用。
