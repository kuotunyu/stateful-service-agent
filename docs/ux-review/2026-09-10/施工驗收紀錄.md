施工基準：`build/local-mvp` 的 `ed1dd5c`，包含上一輪版本、對話及評分修正。原體驗報告基準 `540bc64` 保持原樣。本輪由使用者批准依 UX 計畫執行。

本輪使用獨立臨時 SQLite 與測試服務，不讀 `.env`、不執行付費評估、不重啟 8765。原始體驗截圖不視為改善後證據。

後端測試命令：

```powershell
uv run --no-env-file pytest -q tests/test_ux_validation.py tests/test_edge_cases.py tests/test_api.py tests/test_service.py tests/test_recovery.py tests/test_review_core.py
```

涵蓋：新草案替代舊確認、錯誤請求重播、兩筆預約指定改期、過去時間清除、反悔後不復活、schema 越權不產生草案、未知日期不猜測。測試是工程驗證，不宣稱模型能力。

獨立瀏覽器檢查：

```powershell
uv run --no-env-file pytest -q tests/test_ux_evidence.py tests/test_browser.py::test_evidence_browser_filters_failure_and_preserves_mobile_layout
uv run --no-env-file pytest -q tests/test_ux_accessibility.py
```

分別為 4 passed 與 5 passed。後者涵蓋 390／680／900／1280 寬、主要控制項 44×44、實際計算色彩對比、reduced-motion、Enter／Shift+Enter／IME、重新查詢保留聊天 DOM 與閱讀捲動位置。

T08 審查另外修正：重新載入真的捲到所選案例；切換至不包含該案例的篩選時清除舊 hash，避免重載跳回失敗篩選。保存回覆可能來自確定性系統提示，因此標為「評估保存回覆」，不一律冒稱模型原文。歷史評估資料未改寫。

可靠性審查另補 `test_ux_uncertain_browser.py`：先讓 HTTP 確認實際提交，再中斷回覆並封鎖後續 state 讀取。測試曾明確失敗於結果區錯稱「正在等待你的確認，預約尚未修改」，修正後通過；確認區及結果區持續顯示未知，過期不提供重新填寫，恢復連線並查證兩次仍是一筆版本 1。這與既有故障注入測試分開。

## 驗證界線

主要配色對比量測（WCAG 相對亮度公式）：正文 `#17324d`／白底 **13.13:1**；輔助文字 `#536a7e`／白底 **5.63:1**；白字／藍按鈕 `#126c9c` **5.75:1**；正文／黃確認單 `#fff0b3` **11.48:1**；輸入邊界 `#657f93`／白底 **4.19:1**。裝飾分隔線保留淺色，必要控制項邊界另用深色。

- 本輪沒有付費模型請求，不能用這些結果宣稱新版 Luna 能力。
- 未使用 NVDA 或同級實際讀屏工具；DOM 與鍵盤檢查不等於讀屏驗收。
- 200% CSS zoom 下 1280 視窗量測 scrollWidth=1280，沒有整頁水平溢出；這不等於原生瀏覽器 200% zoom 已驗證。
- 尚無正式無障礙認證；對比量測針對本輪主要文字及控制項，不宣稱窮盡所有狀態。
