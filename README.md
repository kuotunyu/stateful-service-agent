# Stateful Service Agent

### 讓 Agent 的每一次操作，都有資料庫證據。

以模擬維修預約實作的可靠業務 Agent。支援對話與表單查詢、建立、改期及取消，將 LLM 提議、使用者授權與 SQLite 交易分開處理；即使使用者反悔、工具回覆遺失或程序重啟，也能查證操作的最終結果。

**Python · FastAPI · SQLite · GPT-5.6 Luna · Playwright**

## 三個關鍵設計

| 問題 | 實作方式 |
|---|---|
| 模型提議正確，就能直接執行嗎？ | 身分由 server session 提供；使用者確認後，再檢查授權、期限與預約版本。LLM 無法自行授權寫入。 |
| 使用者反悔，舊回覆才到怎麼辦？ | 持久化意圖版本，使過期確認與遲到提議失效；已提交的預約須另外確認取消。 |
| 逾時後重試，會不會重複預約？ | 預約變更與提交收據在同一個 SQLite 交易保存。沿用原操作查證與恢復，以請求 ID、收據及版本檢查避免重複效果與競爭覆寫。 |

```text
對話／表單 → LLM 提議 → 使用者確認 → 授權與版本檢查 → SQLite 交易
                                                         ↓
                                                   提交收據 → 查證／恢復
```

## 用結果驗證設計

**131 項自動測試通過 Windows CI**，涵蓋重複請求、競爭改期、真實子程序重啟、回覆遺失及完整鍵盤操作。操作錄影附六個 SQLite 檢查點，逐步核對確認前後的資料變更。

另以 **GPT-5.6 Luna** 比較「固定流程＋LLM 意圖解析」與「單一 Agent」：共用工具、政策與模型設定，以資料庫狀態及明確契約判分，不使用 LLM judge。

| 評估 | 固定流程 | 單一 Agent |
|---|---|---|
| 第一輪凍結題組：8 題 | DB 正確 8/8；任務成功 7/8 | DB 正確 8/8；任務成功 8/8 |
| 第二輪針對性評估：6 題 | DB 正確、任務成功皆 6/6 | DB 正確、任務成功皆 6/6 |

第一輪的任務失敗來自拒絕答案未遵守 JSON 格式。兩輪對應不同程式版本，題型部分重疊且樣本小，保留為實測證據，不據此宣稱策略優劣。Mock 測試與真實模型評估分開呈現。

## 本機體驗

Windows 安裝 `uv` 後，在專案目錄執行：

```powershell
.\start.cmd
```

開啟 `http://127.0.0.1:8765`，輸入「預約冷氣維修，明天 10:00」。先預覽再確認，也可展開「可靠性示範」體驗逾時與查證。預設使用免費 Mock，不需要 API key。

[操作、模型設定與測試命令](docs/guide.md)

本專案使用合成資料、單一 server process 與本機 SQLite；定位為可重現的工程展示，未提供正式登入或外部維修服務。實際 NVDA 朗讀驗收仍未完成。
